# 期货 5 分钟 K 线清洗入库设计

## 目标

将 `data/export/*.txt` 中的通达信 5 分钟 K 线清洗后写入现有
`data/ashare_quant.db.futures_min_bars`，使现有回测代码可直接按
`symbol` 和 `timeframe='5m'` 查询。

## 方案选择

1. **复用现有 SQLite 表（采用）**：新增一个批量导入脚本，沿用
   `futures_min_bars` 的主键和字段约定。改动最少，现有回测无需修改。
2. 扩展现有单品种 `import_agl9_data.py`：会继续固化白银专用常量和多周期
   逻辑，不适合 85 个品种。
3. 新建独立期货数据库或新表：可保存持仓量、结算价，但现有回测不能直接
   使用，当前需求不需要。

## 数据流与命名

- 输入：`data/export/*.txt`，GB18030 编码、制表符分隔；跳过标题行、表头和
  `#数据来源` 页脚。
- 品种代码取文件名 `#` 后的代码，去掉末尾 `L9`，再追加 `_IDX`；例如
  `30#AGL9.txt -> AG_IDX`、`30#RBL9.txt -> RB_IDX`、
  `29#PP-FL9.txt -> PP-F_IDX`。
- 时间由 `日期 + 时间` 解析为 `YYYY-MM-DD HH:MM:SS`。
- 写入字段为 `symbol, timeframe, trade_time, open, high, low, close,
  volume, amount`，其中 `timeframe='5m'`，`amount=close*volume`，与现有表约定
  一致。
- 当前表和回测均不使用持仓量、结算价，因此不新增字段。

## 清洗规则

- 日期和时间必须可解析；OHLC 必须是有限正数；成交量必须是有限非负数。
- 必须满足 `high >= open/close/low` 且 `low <= open/close/high`。
- 删除同一品种同一时间的重复记录，保留文件中最后一条，并按时间排序。
- 页脚、空行和无法通过上述规则的记录不入库，汇总报告原始、有效、重复和
  无效行数；某个文件没有有效行情则整个导入失败。

## 写入与失败处理

- 仅替换本次 85 个品种的 `5m` 数据，不修改其他品种和其他周期。
- 使用 SQLite 单事务完成删除和批量写入；任一文件解析或写入失败时回滚，
  防止数据库处于半导入状态。
- 依靠现有 `(symbol, timeframe, trade_time)` 主键保证幂等。

## 验证

- 先用临时文件和临时 SQLite 数据库写一个最小回归测试，验证编码解析、
  无效 OHLC 过滤、重复去除、符号映射和非目标数据保留。
- 全量入库后核对：85 个品种、数据库行数等于清洗有效行数、主键无重复、
  OHLC/成交量约束无违规，并抽样通过现有回测 SQL 读取 `AG_IDX/5m`。
