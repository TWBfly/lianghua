# Lianghua 因果回测与安全进化设计

日期：2026-07-30

## 目标

把当前“全区间训练 + 单股独立回测 + 临时仓位启发式”改造成可验证的闭环：

1. 所有历史决策只使用决策时点已经可见的数据。
2. 收盘生成信号，下一交易日开盘尝试成交。
3. 多股票共享一个现金账户、统一时间轴、持仓和订单队列。
4. 每次候选决策、订单、成交和结果都持久化为经验。
5. 新模型只能作为 Challenger 影子运行，通过多个滚动样本外窗口后才能晋升 Champion。
6. 仓位、最大敞口、最大回撤和熔断属于不可被模型修改的硬风控。

## 非目标

- 本阶段不实现 PPO、SAC 或其他完整强化学习。
- 不允许大模型或模型自动修改 Python 代码。
- 不解析 330 个 TradingView Markdown 文件；保留并修正现有手写因果信号。
- 不引入微服务、消息队列、外部模型注册平台或新数据库。
- 不在历史回测中使用缺少披露时间的当前基本面、公告或新闻。
- 不接真实券商；先提供确定性的组合模拟器和未来券商适配边界。

## 方案比较

### 方案 A：继续扩展 `backtest_kline_engine.py`

改动文件最少，但会把模型训练、订单执行、经验存储和模型晋升继续堆进已经超过 600 行的文件。测试隔离困难，后续实盘适配容易再次复制逻辑。

### 方案 B：三个小边界，SQLite 继续作为唯一状态存储（采用）

- `ml_ensemble.py`：只负责因果特征、标签和 walk-forward 预测。
- `portfolio_simulator.py`：只负责统一账户、订单、成交和市场约束。
- `learning_loop.py`：只负责经验存储、重训触发、模型版本和晋升门槛。
- `backtest_kline_engine.py`：降为编排层，调用上述模块并格式化 Web 返回结果。

这是满足当前目标的最小可维护拆分，不新增基础设施。

### 方案 C：完整事件溯源交易引擎

为每个行情、信号、订单和成交建立事件流，扩展性最好，但会引入大量框架和迁移工作。当前数据量与单机 Web 应用不需要。

## 总体数据流

```text
历史可见行情
    ↓
因果特征与 walk-forward 模型
    ↓
T 日收盘候选决策
    ↓
写入 experiences（包括 HOLD）
    ↓
T+1 日开盘订单校验
    ├─ 资金不足 / 停牌 / 涨跌停 → REJECTED
    └─ 可成交 → FILLED
                     ↓
              统一现金和持仓
                     ↓
          5日到期或真实平仓后回填结果
                     ↓
       每周或累计 50 个完成经验触发 Challenger
                     ↓
        多窗口样本外评估 + 影子运行
                     ↓
              晋升 / 拒绝 / 回滚
```

任何回测日期 `t` 的预测模型，训练标签的结果日期必须严格早于 `t`。

## 因果数据与模型

### 特征

- 价格、成交量、滚动均线、波动率和手写 TradingView 信号只能使用当前行及过去行。
- 删除历史路径中的 `bfill` 和 `reindex(method="nearest")`。
- 滚动窗口未成熟时保留缺失值；交易逻辑跳过 warm-up 日期，模型输入在训练与推理时统一用 `0` 填充。
- `TradingViewAllSignalsEngine.generate_all_signals()` 不再调用未来收益 IC 筛选，直接返回现有手写信号。
- 历史回测不读取 `stock_basic` 当前估值、最新财报、最新公告或 DeepSeek 结果作为当日决策输入。

### 标签

- 标签是 `t` 收盘到第 5 个后续交易日收盘的净价格收益是否超过 `1.5%`。
- 最后 5 个未知标签保持 `NaN`，不得转换为负样本。
- 每条训练记录同时保存 `label_end_time`，walk-forward 训练要求 `label_end_time < prediction_time`。

### Walk-forward

- 最少 120 个成熟样本后训练。
- 初始模型只使用预测日期之前已经成熟的标签。
- 每 5 个交易日或累计 50 个新完成经验重训一次；两次重训之间复用同一模型预测。
- 使用现有 LightGBM；XGBoost、CatBoost 和 stacking 不进入第一版因果路径。
- 模型缓存键至少包含：股票、训练截止日期、数据哈希、特征清单哈希和代码版本字符串。
- 回测输出同时包含每个预测使用的 `model_version` 和 `trained_until`。

## 统一组合模拟器

### 状态

- 一个 `cash`。
- `positions[symbol]` 保存股数、平均成本、最高价和建仓时间。
- 一个按执行日期索引的订单队列。
- 每个交易日先处理上一收盘产生的订单，再用当日收盘生成下一交易日订单。

### 订单和成交

- 买入股数向下取整到 100 股。
- 资金不足时拒单，不借款，`cash` 永远不能为负。
- 单股票目标市值不超过初始权益的 20%。
- 总股票敞口不超过当前权益的 90%。
- 买单以次日开盘价加滑点成交；卖单以次日开盘价减滑点成交。
- 佣金、最低佣金、过户费和印花税沿用当前参数，但集中在一个费用函数。
- 订单有效期为一个交易日。

### 市场约束

- 当日没有该股票行情或成交量小于等于 0：按停牌拒单。
- 普通股票涨跌停幅度 10%；`300`、`301`、`688` 开头为 20%；`4`、`8` 开头为 30%；名称包含 `ST` 为 5%。
- 买入开盘价达到涨停价时拒单；卖出开盘价达到跌停价时拒单。
- 涨跌停价由上一有效收盘价计算，比较保留两位小数。
- 回测最后一个交易日按收盘价减卖出滑点强制平仓，并计入完整卖出费用。
- 最大回撤从统一日权益曲线计算，不允许常量或单股结果线性缩放。

### 硬风控

以下参数由程序配置固定，模型输出不能覆盖：

- 单股最大仓位：20%。
- 总敞口上限：90%。
- 单日权益亏损达到 3% 后，当日不再接受新买单。
- 组合从历史高点回撤达到 10% 后触发熔断，只允许减仓和平仓。

## 经验闭环

SQLite 新增 `experiences` 表：

| 字段 | 含义 |
|---|---|
| `decision_id` | 全局唯一决策 ID |
| `run_id` | 一次回测、模拟盘或实盘运行 ID |
| `decision_time` | 信号生成时间 |
| `symbol` | 股票代码 |
| `features_json` | 当时可见的模型输入 |
| `feature_hash` | 特征内容哈希 |
| `model_version` | 生成决策的模型版本 |
| `action` | `BUY`、`SELL` 或 `HOLD` |
| `desired_shares` | 目标订单股数 |
| `order_status` | `PENDING`、`FILLED`、`REJECTED` 或 `NONE` |
| `fill_time` / `fill_price` / `fees` | 成交事实 |
| `exit_time` / `exit_price` | 平仓事实 |
| `horizon_return` | 决策后 5 个交易日净收益 |
| `trade_return` | 实际平仓净收益 |
| `mfe` / `mae` | 决策后的最大有利/不利波动 |
| `reward` | 扣费且带回撤惩罚的学习奖励 |
| `completed` | 结果是否成熟 |

要求：

- 每个交易日每只候选股票都记录决策，包括 `HOLD` 和被风控拒绝的订单。
- 5 个交易日后回填 `horizon_return`、`mfe`、`mae`。
- 平仓后回填 `trade_return`。
- `reward = trade_return - 0.25 * abs(mae)`；没有实际交易时使用 `horizon_return`。
- 写入使用参数化 SQL 和事务；相同 `decision_id` 重放时保持幂等。

## 重训与安全进化

SQLite 新增 `model_versions` 表：

| 字段 | 含义 |
|---|---|
| `version` | 唯一模型版本 |
| `symbol` | 股票代码；首版保持单股模型 |
| `status` | `CHALLENGER`、`SHADOW`、`CHAMPION` 或 `RETIRED` |
| `trained_until` | 训练数据截止日期 |
| `data_hash` / `feature_hash` | 可复现性 |
| `artifact_path` | 模型文件 |
| `metrics_json` | 多窗口评估结果 |
| `shadow_samples` | 已完成影子样本数 |
| `created_at` / `promoted_at` | 生命周期时间 |

### 重训触发

满足任一条件创建 Challenger：

- 距上次训练已经 7 天且存在新完成经验；
- 新完成经验达到 50 条。

### 样本外门槛

至少使用 3 个按时间滚动且标签不重叠的验证窗口。Challenger 相对当前 Champion 必须同时满足：

- 扣除费用后的验证总收益更高；
- 最大回撤不增加；
- 换手率不超过 Champion 的 110%；
- Brier Score 不高于 Champion；
- 每个窗口都没有触发 10% 组合熔断。

### 影子与晋升

- 通过离线门槛后状态改为 `SHADOW`，只记录预测和虚拟订单，不影响真实/主回测订单。
- 至少积累 50 个成熟影子决策后，再用同样门槛比较影子结果。
- 二次通过后，在一个 SQLite 事务内把旧 Champion 改为 `RETIRED`，新版本改为 `CHAMPION`。
- 加载失败、指标缺失或事务失败时继续使用旧 Champion。
- 人工可将任意历史 `RETIRED` 版本重新设为 Champion，实现回滚。

## API 与 Web 兼容

- 保留 `/api/run_backtest` 和 `/api/run_portfolio_backtest`。
- 单股接口改为调用统一组合模拟器的单股票模式，避免两套成交规则。
- 返回字段继续保留现有图表和交易列表所需数据。
- 新增但不要求前端立即展示：
  - `run_id`
  - `model_versions`
  - `rejected_orders`
  - `experience_stats`
  - `evolution_status`
- 历史回测中 DeepSeek 和当前财报只作为页面旁路信息，不影响回测交易。

## 错误处理与安全

- 所有股票、日期 SQL 改为参数化查询。
- 股票代码只允许 6 位数字。
- 日期必须是 ISO `YYYY-MM-DD` 且开始日期不晚于结束日期。
- 模型文件只从 `model_versions.artifact_path` 指向的项目模型目录加载。
- DeepSeek 请求恢复系统默认 TLS 证书校验。
- 模型训练失败、数据不足或 Challenger 不通过时，保持当前 Champion；没有 Champion 时使用因果规则评分。

## 测试策略

新增小型确定性测试，不依赖网络和真实数据库副本：

1. 标签末尾 5 行为 `NaN`。
2. 日期 `t` 的模型训练集中不存在 `label_end_time >= t`。
3. 因果信号前缀在追加未来数据后保持不变。
4. 收盘信号不会在同一天成交。
5. 资金不足拒单且现金不为负。
6. 买入股数始终为 100 的整数倍。
7. 停牌、涨停买入和跌停卖出被拒绝。
8. 多股票同时买入共享同一现金余额。
9. 末日持仓全部平仓并计入费用。
10. 经验写入和结果回填可以幂等重放。
11. 50 个完成经验或 7 天触发重训。
12. 任一晋升指标不满足时 Challenger 不会成为 Champion。
13. 满足离线、影子样本和二次门槛时事务化晋升。
14. 小资金回测不再产生复数年化收益或异常。

## 验收标准

- 全部新增测试通过，原有 Python 文件可以编译。
- 搜索历史回测执行路径，不存在 `bfill`、未来 `nearest` 对齐或全区间未来收益特征筛选。
- 任意交易日预测都能报告模型训练截止日期，并满足截止日期早于预测日期。
- 组合模拟过程中现金始终大于等于 0，最终持仓为 0。
- 最大回撤来自权益曲线计算。
- SQLite 中可以从决策追溯到模型版本、订单、成交和最终奖励。
- 未通过两阶段门槛的模型不能替换 Champion。
- 现有两个回测 API 仍返回前端所需核心字段。

## 延后条件

只有同时满足以下条件，才开始 contextual bandit 仓位学习：

- 至少 1,000 个成熟候选决策；
- 至少 200 笔真实或模拟闭环交易；
- Champion/Challenger 晋升和回滚已经稳定运行；
- 统一模拟器与实际成交的费用和滑点误差有持续监控。

完整 DRL 继续延后到有可靠逐笔或分钟级成交环境之后。
